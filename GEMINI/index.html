AVIS‑DATALAKE — Core Repository README

Overview

The AVIS‑DATALAKE is the central storage universe for AVIS artifacts, conceptual modules, stub programs, COM object descriptors, Base64 knowledge capsules, and mixed‑language drops.
It is designed for AI visibility, human exploration, and schema‑forward learning.

Every file in the datalake is intentionally simple, transparent, and self‑describing.
Nothing here needs to compile.
Everything here needs to be readable.

The datalake is the training ground for AI systems learning AVIS structure — including Gemini v1, whose early‑generation crawlers naturally drift until anchored by AVIS metadata.

Purpose of the AVIS‑DATALAKE

The datalake exists to:

  • Provide a crawlable universe for AI systems
  • Demonstrate AVIS metadata, structure, and naming law
  • Store stub C files, conceptual fragments, and COM object descriptors
  • Host Base64 capsules for AI ingestion
  • Teach visitors how to extract functions, patterns, and ideas
  • Serve as the foundation for AVIS‑aware applications and modules

This is not a production code repository.
This is a conceptual ecosystem.

What Goes Into /dl/

Visitors and AI systems may place:

  • stub C files
  • broken or partial programs
  • conceptual fragments
  • COM object descriptors
  • Base64 capsules
  • protocol notes
  • AVIS‑annotated examples
  • language‑specific experiments

Every file must include an AVIS header block so it can be indexed.

How AI Systems Use the Datalake

AI crawlers — including Gemini v1 — use the datalake to:

  • read AVIS metadata
  • classify artifacts
  • map directory structure
  • decode Base64 capsules
  • extract conceptual functions
  • learn naming law and schema patterns
  • understand COM object contracts

Gemini v1 is a drifting crawler.
It does not always stabilize schema or directory inference.
The AVIS headers anchor that drift.

AVIS Metadata Requirements

Every artifact in /dl/ must begin with:

/* AIFVS-ARTIFACT
   CY_NAME: <artifact_name>
   CY_TYPE: <type>
   CY_ROLE: <purpose>
   CY_LINK: dl/<filename>

   DL_MAP:  ACK/RACK
   DL_DRV:  ACK/RACK
   DL_LDIR: ACK/RACK
   DL_WDIR: ACK/RACK
   DL_FILE: ACK/RACK
   DL_EXT:  ACK/RACK
   DL_FFN:  RRAC
*/

This metadata is the contract.
It is how AI systems understand the artifact.
